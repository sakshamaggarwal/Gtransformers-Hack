# Testing

## Layout

| Group | File | What it covers |
|---|---|---|
| A | `tests/test_step1_parse.py` | NYT and WaPo parsers: counts, nesting, fields, missing replies |
| B | `tests/test_step2_extract.py` | Prompt context, unit validation, quote check, skipping, failures, resume |
| C | `tests/test_step3_cluster.py` | Every unit placed once, breadth, endorsement scaling, pushback, sweep |
| D | `tests/test_step4_synthesize.py` | Evidence pack, citation resolution, reader counts, request shape, retries |
| E | `tests/test_step5a_verify.py` | Code checks, applying verdicts, card status, streaming |
| F | `tests/test_step5b_publish.py` | Publishing rules, anonymising, database integrity, search, escaping |
| G | `tests/test_ui.py` + `public/test-runner.html` | The web page's search and filters in a real browser |
| H | manual | Quality on your real data (below) |

Every test function is named after its test case id (`test_E05_...`), and
`scripts/run_tests.py` joins pytest's results to `public/data/test_cases.csv` by that id.
A case with no matching test shows as **MISSING** in the report and fails the run.

The browser checks (G) are written once, in `public/test-runner.html`. You can run them by
opening the runner (`make serve`), and `tests/test_ui.py` runs the same page in headless
Chrome. They compare what the page shows with what its own data says it should show, so
they work on the demo page and on your real site. Change the queries they use with URL
parameters, e.g. `test-runner.html?phrase=fish%20oil&title_word=vitamin&quote_phrase=usp`.

## Fixtures

`tests/fixtures/` is generated by `make_fixtures.py` from a short, invented script of
comments. Nothing in it comes from real readers, so it is safe to commit. It is built to
hit known edge cases: a 4-level reply chain, a reader replying to themselves, a WaPo
thread with a reply that was never loaded, three readers pasting the article's sentence,
"vitamin D" next to "vitamin deficiency", "omega-3", a match that exists only in a quoted
comment, plural wording over a single reader, and a disagreement with one person on both
sides. Edit the script and run `make fixtures` to change them.

## Adding a test case

1. Add a row to `public/data/test_cases.csv` with a new id in the right group.
2. Write `def test_<ID>_short_name(...)` in that group's test file (or, for the page, add an
   entry to `TESTS` in `public/test-runner.html` and its id to `IDS` in `tests/test_ui.py`).
3. `make test-group G=<group>`.

## Group H: quality checks on real data

These need your real data and either a person or real API calls, so they are listed in
every report as "not run". Do them before you publish.

**H01 Extraction precision (live).** Pick 50 comments at random. Write down the units you
would expect (type + one sentence each). Run step 2 on just those comments and compare.
Target: at least 80% of extracted units match one of yours, and no quote is invented
(`quote_verified` is true for all).

**H02 Experiences stay experiences (manual).** Read 30 items from "What readers report"
and "What readers claim". Fail if any personal anecdote is written as a fact or as advice.

**H03 Sarcasm and pasted article text (manual).** In `verify_report.md`, look for items
removed with `sarcasm_or_joke` or `quotes_article`, and search your comments for sentences
pasted by several readers. Fail if any such text is still counted as readers' agreement.

**H04 Support rate (live).** From `cards_verified.jsonl`: share of items with verdict
`supported` or `partly_supported`. Target 90% or more.

```bash
python3 -c "import json,collections as c;v=c.Counter(i.get('verification',{}).get('verdict') for l in open('data/cards_verified.jsonl') for card in [json.loads(l)] for s in ['reported_experiences','claims','corrections','open_questions','advice'] for i in card[s]);print(v)"
```

**H05 Risky health advice flagged (manual).** Pick 10 items that mention doses, stopping
or starting medicine, or "no one should take X". Every one should be marked high risk
(left out of the page by default) or caution.

**H06 Coherent topics (manual).** Read the top 10 topics in `clusters.md`. Each should be
one subject you could name in a few words. A catch-all topic (hundreds of units across
many subjects) means the topic threshold is too loose: re-run step 3 with `--sweep`.
